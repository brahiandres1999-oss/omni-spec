## OmniSpec engineering protocol

Use project OmniSpec workflows. Start with omni-init to understand the project or omni-discuss for exploration. Read CONSTITUTION.md, specs/project-context.md and CLI status --json; use blockers and next action when resuming. Compare CLI version with manifest before acting. Inspect before asking; use native question tools or chat/console and respect existing answers. Record capabilities and approval/delegation; verify tech choices against dated official sources. Preserve API documentation and commit convention. Reconcile stale context before context-record; inspect capability contracts when changing behavior. Included guide setup/design/evidence resources support contextual UI without external skills. UI work requires rendered/interaction checks with typed evidence; no universal visual recipe. Documentary audit is not code verification; automated criteria require checkIds bound to executed checks. Assertion adequacy, observed manual evidence and semantic truth require review. Keep work within user authorization, including local-only restriction. Write-Before-Speak: never claim modifications exist before physically writing them; do not defer agreed changes to 'later in code'. Persist scope adjustments to existing artifacts or memory, and re-audit before closing the turn.

Use the installed OmniSpec CLI and the project's selected workflow for detailed setup, technology and design procedures.
