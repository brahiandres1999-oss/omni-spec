# OmniSpec 0.7.0-rc.2 — candidato local

Segunda candidata de 0.7.0. Corrige los defectos encontrados al evaluar rc.1 con proyectos realistas (Playwright, Gradle, IDE, monorepos y Windows) y mantiene los contratos de rc.1: cierre con evidencia tipada, catálogo de checks por módulo, estado de entrega, contexto con baseline, decisiones, contratos de capacidad y fit según riesgo.

No se ha publicado. Las comprobaciones locales y del paquete no sustituyen el piloto del usuario ni una evaluación comparativa entre hosts y modelos.

## Cambios principales

- **Verificación que funciona con salidas generadas.** La huella respeta `.gitignore` (raíz y anidados), `.git/info/exclude`, un `.omnispecignore` opcional con la misma sintaxis y exclusiones por defecto (`test-results/`, `playwright-report/`, `.gradle/`, `.idea/`, `.vscode/`, `build/`, `target/`, `coverage/`, etc.). Las reglas se comprueban contra `git ls-files --exclude-standard` en 93 casos. Si un check escribe un archivo no ignorado, `verify` falla y nombra la ruta.
- **Contexto sin falsos obsoletos.** El baseline cubre `project-context.md`, los archivos que enlaza, manifiestos de build/dependencias/runtime, CI e instrucciones de agentes. Implementar código ya no obliga a ejecutar `context-record` antes de cada `verify`.
- **Comandos responsivos durante verify.** Los checks corren bajo un bloqueo de verificación propio. `session-record` y `decision-record` no esperan, y `complete` no se cruza con una verificación en curso.
- **Evidencia de UI que no caduca.** Se conserva el historial de sesiones. Una observación sigue siendo válida en la sesión donde se hizo, con precisión de segundos.
- **Entradas JSON fuera del proyecto.** `--from` acepta cualquier ruta o `-` para stdin. `guide evidence` documenta la forma exacta de fit, checks, aceptación, sesiones y decisiones, y recomienda `specs/.omni/inputs/`.
- **`clean` seguro.** Elimina solo copias administradas sin modificar del runtime y de las skills `omni-*`. Conserva las skills del usuario, los respaldos y los archivos no registrados, y rechaza adaptadores que necesitan el runtime local.
- **Sin gates implícitos.** `init --yes` registra los scripts detectados como candidatos, no como gates obligatorios.
- **Robustez en Windows.** Las escrituras atómicas reintentan EPERM/EBUSY/EACCES transitorios (OneDrive, antivirus). Una copia CRLF de los archivos administrados no se trata como edición local (update, doctor y clean). El wizard acepta respuestas por tubería y conserva el prompt al editar en terminal.
- **Registros portables.** `verification.json` pasa a la versión 3: `checkCwd` relativo, orden independiente del locale, lista de archivos cambiados y número de archivos atestados. Mover la carpeta del proyecto ya no invalida una verificación.
- **Git local ordenado.** `specs/.gitignore` recibe una sección administrada con el estado local (logs, backups, inputs, locks) sin reemplazar reglas propias. `update` deja `specs/.omni/reference/CONSTITUTION.md` para comparar una constitución preservada con la guía actual.

## Migración desde rc.1 o 0.6.x

1. Ejecutar `update --dry-run` y revisar los conflictos, luego `update`.
2. Volver a ejecutar `verify` en las specs en curso: los registros de versión 2 se rechazan con un mensaje explícito. Las specs completadas no cambian.
3. Un baseline de contexto anterior se compara solo sobre las entradas de contexto actuales. `status` sugiere ejecutar `context-record` para adoptar el nuevo alcance.
4. Si un check escribe salidas en rutas no ignoradas, añadirlas a `.gitignore` o `.omnispecignore`.

Las reglas de ignorado de carpetas superiores al proyecto no se aplican: un repositorio padre no puede desactivar la atestación. En un monorepo, lista las salidas adicionales en el `.omnispecignore` del paquete. La comparación distingue mayúsculas en todos los sistemas: los mismos bytes producen la misma huella en Windows, macOS y Linux. Una copia con finales de línea CRLF tiene otros bytes y requiere su propia verificación.

Consultar [DELIVERY](../DELIVERY.md) para formatos y [COMPATIBILITY](../COMPATIBILITY.md) para límites.
