# OmniSpec 0.8.0-preview.1 — 0.8.0 Preview

**Preparada para lanzamiento; publicación pendiente.** Canal npm `preview`; GitHub prerelease. `latest` conserva 0.6.1 (consultado el 2026-10-28).

Esta versión preliminar incorpora las primeras mejoras del paradigma de trabajo de OmniSpec 0.8, consolidando los aprendizajes del piloto IPS y corrigiendo defectos de aislamiento, observabilidad y coexistencia.

---

## Cambios de comportamiento al actualizar desde 0.7.0-preview.2

1. **Constitución ligera y referencias modulares**
   - *Qué cambia:* Las nuevas inicializaciones reciben una constitución simplificada con enlaces modulares a las guías empaquetadas (`guide setup`, `guide design`, `guide evidence`).
   - *Para proyectos existentes:* `update` no sobreescribe tu `CONSTITUTION.md` existente; genera `specs/.omni/reference/CONSTITUTION.md` como copia de referencia para comparaciones sin modificar tus reglas acordadas.

2. **Runtime local excluido de Git y restauración con `update`**
   - *Qué cambia:* La ruta `specs/.omni/runtime/` se añade a la sección gestionada de `specs/.gitignore` para evitar contaminar el historial del repositorio.
   - *Para proyectos existentes:* `update` restaura o reemplaza el runtime desde el paquete según la versión declarada en `specs/manifest.json`. Si el repositorio ya versionaba el runtime, los archivos siguen en el índice hasta ejecutar `git rm -r --cached specs/.omni/runtime` y hacer commit.

3. **Salida compacta en `status --json` y selección con `readSet`**
   - *Qué cambia:* Para preservar el presupuesto de contexto de los agentes, `status --json` omite la aceptación de especificaciones no activas y las decisiones que solo aplican a especificaciones cerradas.
   - *Para proyectos existentes:* El total de omisiones se reporta en `progress.omitted`. La bandera `--all` (`status --json --all`) recupera la estructura completa. Además, `readSet` lista exactamente los archivos necesarios para la spec activa.

4. **Línea base de contexto `CONTEXT_INPUTS_V3`**
   - *Qué cambia:* Comparación y verificación de huellas normalizada e insensible a saltos de línea CRLF/LF en archivos de texto rastreados.
   - *Para proyectos existentes:* Evita falsos positivos de estado `STALE` tras conversiones de Git o clonados en entornos multiplataforma (Windows y Linux/macOS). Un CLI 0.7.x trata V3 como antigua, puede marcarla `STALE` y puede volver a registrarla como V2. Todo el equipo debe usar la misma versión de OmniSpec.

## Nuevas características y mejoras

- **Coexistencia del plugin de Antigravity (Spec 012):**
  - Detección de solo lectura en `doctor` y `plugin install/update/upgrade`, alertando de duplicación de comandos sin modificar archivos.
  - El asistente `init` ofrece elección interactiva entre *Modo Proyecto* (`antigravity`) y *Modo Plugin* (`plugin`) para nuevos proyectos con Antigravity como única herramienta.
  - Proyectos mixtos (`antigravity,claude` o `all`) conservan adaptadores locales y reciben explicación informativa sin sugerir `clean`.
- **UI Companions y Sinergia Frontend (Spec 014):**
  - Detección en `init` de dependencias de UI, Tailwind CSS y kits de componentes (`shadcn`, `radix`, `headlessui`, `preline`, `flyonui`).
  - Asistente interactivo adaptativo (TUI y texto plano) que consulta kit de componentes y companion solo cuando detecta señal de interfaz, con soporte completo para flags `--ui-companion` y `--ui-components`.
  - Catálogo curado y empaquetado sin dependencias externas: guías `better-*` (accesibilidad, diseño, contraste, microcopia) y `frontend-design` (dirección de arte), gestionadas en `specs/.omni/companions/<nombre>/` sin contaminar comandos de host.
  - Subordinación explícita: la guía de diseño y la constitución de OmniSpec prevalecen sobre las heurísticas de cualquier companion, evitando código defensivo o enmascaramiento de errores.
- **Economía de contexto y presupuestos (Spec 008):**
  - Nuevo comando `contracts --active` y límites explícitos de caracteres en prompts para evitar desbordamiento en ventanas de contexto reducidas.
- **Observabilidad e ingeniería de prompts (Spec 010):**
  - Sección obligatoria de Observabilidad en las plantillas `plan.md` y `fix.md`.
  - Matriz de cinco estados en la sección de experiencia de `spec.md` y contrato de dirección de arte en `guide design`.
- **Infraestructura y empaquetado seguro (Specs 002 a 006):**
  - Limpieza automática de temporales en `package-smoke` y nuevo comando `npm run pack:dev` para generar tarballs de desarrollo identificables.
  - Matriz de validación en CI con soporte completo para Node.js 26.x y ramas `next/**`.
  - Manejo seguro de pruebas de versiones futuras y soporte para filas `DECISION` en especificaciones de tipo RFC.
  - Inclusión de esquemas y licencia en el plugin global, con intento de limpieza de una copia incompleta si falla la copia. La instalación sustituye el destino y copia por pasos; no es atómica.

## Validación de esta candidata

El cierre inicial registró 372 pruebas del motor y 13 pruebas de coexistencia. La auditoría posterior encontró recorridos omitidos y evidencia insuficiente; esos totales históricos no acreditan toda la candidata.

Las correcciones de la spec 013 añaden regresiones para flags interactivos, validación de respuestas, cancelación/EOF, lectura previa a instalación, archivos regulares, TUI con teclado y actualización desde subcarpetas.

La verificación local del 2026-10-28, a las 21:33:32 UTC, aprobó los 18 controles configurados en Windows / Node v24.22.1: motor 409/409, suite específica de companions 31/31, lint, pruebas de empaquetado y metadatos de release. La regresión de rangos npm vacíos se comprobó antes y después de corregirla, con una matriz de 240 combinaciones que también preserva los campos históricos del detector. El tarball se ejercitó con ambos companions y en modo plugin.

El usuario confirmó legibilidad, foco con flechas y cancelación de las preguntas de companions en ventana amplia y pequeña. Esa observación corresponde a UI companions (014); no acredita el selector de coexistencia de 012 ni la activación de Antigravity. La revisión de interacción de coexistencia y los recorridos en hosts reales siguen pendientes. La CI del commit de integración y del tag deberá comprobarse antes de distribuir los artefactos.

## Alcance de esta entrega y trabajos posteriores

Presets, importación/exportación de configuración y el puente para un futuro Initializr web (015), así como avisos de versiones remotas y sincronización explícita de companions (016), quedan para una versión posterior del mismo paquete. No se incluyen `--preset` ni `update --companions` en esta Preview. Se conserva el resto del plan de 0.8 en la [hoja de ruta](../ROADMAP.md).

## Límites conocidos

- La presencia del plugin global no deduplica visualmente el selector nativo del host en Antigravity (hallazgo E-03).
- La migración de un proyecto existente a modo plugin sigue siendo un proceso deliberado del usuario mediante `clean --dry-run` y `clean`.
- La observación integrada del selector de coexistencia (012) y los recorridos reales de aceptación de Antigravity siguen pendientes. La presencia del plugin no demuestra que el host lo activó. La observación manual de las preguntas de companions (014) se limita a esas preguntas.
- Siguen para preview.2 fit v3, rojo→verde, auditoría de Observability/estados, destilación de memoria y resto de E-02. La coexistencia de 012 se adelantó al candidato actual de preview.1; no equivale a deduplicación del host.
- `init` y `update` pueden conservar/generar runtime local en modo plugin; cambiar de agente no borra archivos anteriores.
- La alternativa `npx` fijada por versión no distingue un paquete enlazado con esa misma versión.
- El runtime gobernador del espacio raíz se mantiene en `0.7.0-preview.2` hasta la publicación formal en npm.
- El catálogo de UI companions se distribuye empaquetado con la herramienta; ejecuciones desde el runtime local aislado (`specs/.omni/runtime/`) no incluyen la carpeta `companions/` y omiten la sincronización de companions emitiendo un aviso informativo (requiere `npx omni-spec@<version> update`).
- La skill comunitaria `ui-ux-pro-max` quedó excluida del catálogo empaquetado para evitar dependencias de Python 3, fuentes pesadas y un aumento de ~22 MB en el paquete npm.
